# 架构术语学习通

像背单词一样学习中文架构术语、也支持刷软考系统架构设计师历年真题的轻量 Web 应用。零依赖、无需构建，双击即可用。

> **移动端版**：已全面改造为移动优先的 PWA —— 底部 Tab 导航、滑动手势评分、刘海屏安全区适配、可「添加到主屏幕」当独立 App 使用，Service Worker 离线缓存，断网也能学。

## 运行

三种方式任选：

1. 直接双击 `index.html`（需联网以加载 Supabase SDK 并登录；数据存在浏览器 localStorage）
2. 本地起服务（推荐，便于调试）：

```bash
cd archgo
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

3. **手机随时访问**：直接用下面部署好的 GitHub Pages 地址，不用打包、也不用连同一个 WiFi。

> 学习进度存在浏览器本地；**首次使用需要登录**（见「云端账号同步 → 登录门禁」），手机与电脑登录同一账号即可自动同步，也可以在「设置 → 数据」里用 JSON 导出/导入迁移。

> **安装为手机 App**：手机浏览器打开站点后，Android Chrome 菜单 →「添加到主屏幕」；iOS Safari 分享 →「添加到主屏幕」。安装后全屏独立运行，Service Worker 会缓存全部静态资源，离线可用。

### 构建期自动切换云端环境

开发与生产使用**两个独立的 Supabase 项目**（不是同项目不同表 —— 原因见下文「同步规则」）。切换由流水线完成，**不需要手工改任何配置**：

- `assets/js/config.js` 里同时保存 `prod` / `dev` 两套配置；
- 唯一的开关是该文件中的 `window.SUPABASE_ENV`；
- 构建 `main` 时工作流用 `sed` 把它替换成 `'prod'`；
- 其余情况（本地开发、其他分支、替换失败）一律保持默认的 `'dev'`。

默认值刻意选 `dev`：万一替换步骤失效，线上顶多连到开发库，而不会反过来把**生产数据写进开发库** —— 后者清理成本高得多。替换后会校验生效值，不匹配则构建直接失败并回滚配置，**宁可发不出去，也不发一个连错库的站点**。

## 词库与 BGM

- **100 条术语**，覆盖架构风格、分布式理论、一致性事务、服务治理、数据与存储、消息与异步、领域建模、设计原则、可观测性、云原生运维、安全与身份、性能与容量、交付与工程、API 与集成、前端架构，共 15 类；每条都是 **中文 / 英文 / 日语 一一对应**（日语为 IT 现场常用叫法，如「結果整合性」「サーキットブレーカー」）。
- **BGM** 不是音频文件，而是 `assets/js/bgm.js` 用 Web Audio 实时合成的氛围音：低音 + 四和弦垫（Am7 → Fmaj7 → Cmaj7 → G）+ 五声音阶随机铃音，永不重复、离线可播、零体积开销。
  - 开关键：学习页 `♪ BGM` 按钮、快捷键 `B`，或「设置」里的开关与音量滑杆（设置会被云端同步记住）。
  - 浏览器策略要求先有一次点击/按键才允许出声，所以开启后会在你第一次交互时自动开始播放。
- **音效**同样实时合成，默认开启（可在「设置」里关掉或调音量）：

  | 场景 | 音色 |
  | --- | --- |
  | 答对（认识） | 上行三音 C5–E5–G5，明亮 |
  | 答错（不认识） | 下行两音带轻微下滑，低沉 |
  | 模糊 | 单个中性音，表示「记住了但不牢」 |
  | 翻卡 | 短促清脆的「嗒」 |
  | 切换页面 / 点导航 | 极短轻声点击 |

## 间隔重复规则（`assets/js/srs.js`）

- 记忆等级 `box` 对应复习间隔（天）：`1, 2, 4, 7, 15, 30, 60, 120`
- **不认识**：box 归零，10 分钟后重来，遗忘次数 +1
- **模糊**：间隔按当前等级 ×0.9 倍收缩，至少 1 天后再来
- **认识**：等级 +1，间隔按等级 × 熟练度系数放大
- `box >= 4`（间隔 ≥ 7 天）视为「已掌握」

## 云端账号同步（开箱即用）

已内置 Supabase 项目（`assets/js/config.js`），**无需任何配置**：打开应用 → 在登录门禁处用邮箱或用户名 + 密码注册/登录，手机和电脑多端自动同步进度。

数据表结构：**每个用户一行**，靠 RLS 策略隔离（只能读写 `user_id = auth.uid()` 的那一行）。

```sql
create table if not exists public.progress (
  user_id uuid primary key references auth.users on delete cascade,
  data jsonb not null default '{}'::jsonb,
  updated_at bigint not null default 0
);

alter table public.progress enable row level security;

create policy "own_row" on public.progress
  for all to authenticated
  using ((select auth.uid()) = user_id)
  with check ((select auth.uid()) = user_id);
```

> anon key 是 Supabase 设计上可公开的前端密钥，它对应「未登录匿名角色」，已验证匿名直接查 `progress` 只会返回空数组 —— 真正的边界是上面的 RLS 策略。**千万不要把 `service_role` key 填进去**（它会绕过 RLS）。

2. **Settings → API** 复制 Project URL 和 anon public key

### 登录门禁（未登录不能进入应用）

`assets/js/app.js` 里有一套门禁：**没登录就进不去应用**，首页会整页盖住一层登录卡片，登录（或注册）成功才放行。设计要点：

- **四个状态**：`checking`（启动即盖上，正在读本地会话）→ `locked`（确认未登录）/ `open`（已登录）。`checking` 阶段就先盖住，避免应用先闪一下再被盖住。
- **门禁与账号页共用同一份表单节点**（`#acctAuth` 被 `appendChild` 搬来搬去）。校验、错误提示、防重复提交、邮箱/用户名双支持因此只有一套实现，不存在两个入口行为不一致；`appendChild` 会带着已绑的事件监听一起搬走，不用重新绑定。
- **判定只有一个入口** `applyGate()`，挂在 `Sync.onChange` 上。所以「登录」「退出登录」「token 过期」「别的标签页退出后同步过来」全都自动生效，不靠各按钮的回调去切。
- **门禁期间屏蔽键盘快捷键**。应用本体只是 `visibility: hidden`，键盘事件照样能打到 `#view-learn` 上，不挡住的话空格翻卡 / `1`/`2`/`3` 评分会在未登录时改写本机记录。
- **SDK 没加载出来时不装死**：门禁会显示具体错误（比如「Supabase SDK 未加载，请联网后重试」）并给出「重新加载」按钮。
- 门禁节点缺失时 `ensureGate()` 会用 JS 现场补一个 —— Service Worker 是 cache-first，发布过程中可能出现「新 app.js + 旧 index.html」的错搭，门禁若只写在 HTML 里，那一刻就会整个失效。
- 开发环境在门禁里也会显示黄黑警示条（顶部的 `.env-badge` 此时被盖住了）；生产环境不显示任何痕迹，加 `?env` 可临时自查。

> 门禁只是**界面层**的准入控制：数据本身仍然完全受 RLS 保护，未登录用户即使绕过界面也读不到任何人的数据。

### 换设备时的数据保全

- **术语进度、真题错题本、案例/论文「待巩固」标记**都会随账号同步（早期版本后两者存在独立 localStorage 键里，换设备必丢，现已并入主数据）
- 「设置 → 数据与备份」可**导出 / 导入 JSON**，导入走**合并**，不会抹掉已有卡片
- 覆盖云端、导入、恢复、清空之前都会自动在「本地快照」留一份（最多 5 份），点一下即可回退
- 清空区分「**仅清本机**」（云端不动，重登可恢复）与「**本机 + 云端**」，两者都会先自动备份
- 换设备或清理浏览器前，请在「设置 → 数据」中导出 JSON 备份。
